# 合箱现场试验与承运组合扩围

这是用于包装方案试验与履约资料分析的本地工作区。样例资料为合成数据，不代表真实订单或承运记录。工作区包含 Python 3.11+ 命令入口和 JSON 记录，可离线查看与核验。

## 运行

无需安装第三方依赖。设置 `PYTHONPATH=src` 后运行 `python3 -m parcel-trial-decision` 可查看工作区版本。运行现有基线检查：`PYTHONPATH=src python3 -m unittest discover -s tests -v`。

## 资料

`data/sample.json` 保存小型合成记录，顶层键分别为 assignments, parcels, claims, capacity。

`data/route_trial.json` 来自同一试验仓的分派登记、发运和售后流水。`block` 是按周划分的分派批次，`team` 是该批分派的单位，`choice` 是原分派；实际装箱以 `packages.items` 为准，同一 `bill` 可覆盖数个包裹。账单金额使用分；同一运单在 `invoices` 只有一个基础实付值，订正引用旧条目而不是额外收费。合同档位给出含端点的上限千克数和对应收费，体积重以立方厘米除以合同除数。一个合同期的起止日期均包含当日。

包裹计费重取实重与体积重较大者，按包裹计费时逐件落档；按运单计费时用同一运单内的计费重合计落档一次。没有覆盖该重量的档位时留作无适用合同报价，不推定超重费。

售后关窗在订单发运后第十天登记，`covered` 仅指该条核查覆盖到的物品。破损记录的 `items` 为空表示已报告但无法定位到具体物品，`adjudicated` 为空表示尚未核认。`as_of` 是最初会议取账日；账单或售后事件可以在此日后到达。`signed_scopes` 保留会议时确认的范围和当时引用的订单，不表示当前仍有可用容量或仍处于生效状态。

`data/field_waves.json` 是另一轮现场试验，不能与前述订单混作同一随机试验；订单、包裹、关窗和计费字段含义相同。每批 `block` 的四个 `zone` 各自共用一张操作台，抽签均匀分给两区单班合箱、两区三班合箱。每区四个班组，再在区内均匀抽相应数量的班组，名单在 `treated`；`quota` 是抽中的班组数而不是实际合箱订单数。不同批的抽签独立。`review_plan.eligible_blocks` 是截至该轮允许纳入的分派批次；它不提前确认这些订单都已成熟。`shared_alpha` 是这轮所有同期候选及政策影响判断共用的错误概率预算；`damage_increase_limit` 是相对可比对照允许新增的破损概率（例如 `0.04` 是四个百分点），`damage_rate_limit` 是候选生产条件另外要求的绝对风险上限。`signed_scopes` 记录历史签字，不表示历史判断已被重新证明。所有资料均为本地合成记录。

`future_zones` 记录后续可参加抽签的操作台、当日可用班组及允许抽到的合箱班组数。名单交叠表示同一班组在几个作业区中择一，不表示可在同日重复分派；已确认的班组不可另外使用。`available` 登记一天内的总台位及箱料，`pilot_bookings` 的已确认使用先扣除相应台位和箱料。班组占比是试验处理条件，用箱需求按候选订单件数估计。
